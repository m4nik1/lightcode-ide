Novus UI Audit

Novus was split out of the IDE recently and the UI grew fast. It carries the marks of that: shadcn primitives copied in without the design-token layer they depend on, a theme map that stores every color twice, dead style objects that render nothing, and a handful of state bugs that surface directly on screen. Six phases, ordered so each one clears the ground for the next.

How to read this

Every issue below is behavioral or visual — the typechecker is already green, so none of this shows up in CI. Findings carry one of three weights.

Breaks

The user hits a wall: can't move the window, can't clear a stuck spinner, sees a thread that no longer exists.

Wrong

It renders, but not as intended — silent no-ops, desynced state, missing feedback.

Rough

Works, but reads as unfinished: dead code, mixed conventions, thin polish.

The reference for how this repo already does it right is apps/desktop/src/renderer/index.css — a full shadcn token layer, tw-animate-css, and a scrollbar recipe. Novus should mirror it rather than invent a third convention.

01

Design token foundation

This is the root cause of most of the inconsistency and has to land first. In Tailwind v4 an undefined token emits no CSS at all — the utility class silently does nothing.

  • Wrong

    Every shadcn primitive renders unstyled

    index.css defines exactly one token: --font-sans. But the primitives copied from shadcn reference bg-primary, bg-popover, text-popover-foreground, bg-accent, text-muted-foreground, border-input, ring-ring, bg-border, and text-destructive. None of them exist, so none of them emit anything.

    The symptom is visible in ModelPicker: it has to hand-paint menuSurface and border over the menu to give it a background at all, and passes ring-0 to kill the stray ring-1 ring-foreground/10 — an undefined ring color falls back to currentColor, i.e. a white hairline around the dropdown.

    FixRewrite index.css following apps/desktop/src/renderer/index.css: an @theme inline block mapping --color-* onto the Novus palette, defined once as :root variables. Novus is dark-only, so put the dark values straight on :root — no @custom-variant dark needed, and the dark: variants in the copied primitives become harmless no-ops.

    • src/index.css:1-35
    • ui/dropdown-menu.tsx:44
    • ui/button.tsx:12-21
    • ui/textarea.tsx:10
    • ModelPicker.tsx:76-81
  • Wrong

    Dropdown animations are dead classes

    tw-animate-css is not a dependency of apps/novus, so data-open:animate-in, fade-in-0, zoom-in-95, and slide-in-from-top-2 compile to nothing. Both model dropdowns pop in with zero transition.

    FixAdd tw-animate-css to package.json (desktop already pins ^1.4.0) and @import it at the top of index.css.

    • package.json
    • ui/dropdown-menu.tsx:44,245
  • Rough

    Every color is stored twice

    theme.ts holds the same 17 colors in two shapes: aiTheme as raw hex (for AIWindow's inline styles) and aiThemeClassNames as arbitrary-value strings like bg-[#1B1B1B]. Changing one color takes two edits, and the two copies can drift without anything catching it.

    FixCollapse theme.ts to the handful of composite recipes that genuinely aren't expressible as tokens — raisedSurface, messageSurface, sidebarDepth, primaryAction, stopAction, the layered inset-plus-drop shadows. Delete the ~30 single-purpose entries and use plain semantic classes at the call sites.

    • src/theme.ts:1-61
  • Rough

    Compensating overrides can come out

    Once the tokens resolve, the ring-0, menuSurface, and menuItemFocus patches in ModelPicker are all working around a problem that no longer exists.

    FixRemove them in the same pass, so the next person doesn't inherit the workaround without the reason.

    • ModelPicker.tsx:73-93
02

Window chrome

Novus is frameless on the platform it's being developed on, and nothing replaces the frame.

  • Breaks

    The window can't be moved or closed on Linux and Windows

    main.ts passes frame: false on non-macOS, and AIWindow renders the drag-region top bar only when isMac. On Linux — the current dev platform — the result is a window with no titlebar, no drag region, and no close, minimize, or maximize controls.

    FixRender the top bar on every platform. Then either add custom window controls wired through the preload bridge, or switch main.ts to titleBarStyle: 'hidden' plus titleBarOverlay so the OS keeps painting its own controls.

    • src/main.ts:18
    • AIWindow.tsx:19
    • AIWindow.tsx:74-81
  • Rough

    40px of macOS-only padding on every platform

    SidebarHeader carries pt-10 to clear the macOS traffic lights, applied unconditionally. On Linux and Windows that's just dead space above "New chat".

    FixMake the padding conditional on the same platform flag as the top bar.

    • sidebar/SidebarHeader.tsx:11
  • Rough

    Platform detected via deprecated navigator.platform

    AIWindow reads navigator.platform once at module scope. The API is deprecated, and the renderer already has a proper channel for this kind of fact.

    FixExpose platform from the main process through preload.ts and global.d.ts, matching how openFolder is already bridged.

    • AIWindow.tsx:8
    • src/preload.ts
    • src/global.d.ts

05

Visible-state bugs

These live in the data layer but every one of them is something the user sees. Independent of the styling work, so they can run in parallel.

  • Breaks

    Stop leaves a ghost message shimmering forever

    messageSend inserts an empty assistant message as a streaming placeholder. stopTurn clears isTurning but never removes that placeholder — and ChatMessages renders any empty assistant message as the "Thinking" shimmer. Hit Stop and the thread animates forever.

    FixDrop the empty placeholder in stopTurn, or mark it stopped and render that state.

    • useAIChat.tsx:122-135
    • ChatMessages.tsx:77-86
  • Breaks

    Any network error strands the UI

    messageSend has no try/catch anywhere in its 75 lines. If the server is down or the stream drops, isTurning stays true, the button stays stuck on Stop, the shimmer keeps running, and the user is told nothing.

    FixWrap the send in try/catch/finally, clear isTurning in finally, and render the error on the failed message.

    • useAIChat.tsx:45-120
  • Breaks

    Deleted threads stay on screen

    ThreadItem deletes server-side first, then calls onDeleteThread. But AISidebar.deleteThread opens with if (!currentThread) return — so deleting a thread while none is selected removes it from the database and leaves the row in the sidebar until reload. Separately, deleting the selected thread never clears currentThread, so the transcript keeps displaying a conversation that no longer exists.

    FixDrop the guard, and clear currentThread when the deleted thread is the active one.

    • sidebar/AISidebar.tsx:71-80
    • sidebar/ThreadItem.tsx:18-25
  • Wrong

    New threads race the query and can vanish

    handleNewChat optimistically prepends the created thread to local projects state. The effect below rebuilds that same state from projectsQuery.data. The two write to the same place on different schedules, so a new thread can flicker or disappear.

    FixLet react-query own the list — invalidateQueries after the mutation instead of mirroring server data into useState.

    • sidebar/AISidebar.tsx:61-68
    • sidebar/AISidebar.tsx:82-119
  • Wrong

    The model picker can lie about the active model

    ModelPicker keeps selectedModel and thinkingLevel in local state, duplicating the provider's model — and initializes both to options[0] regardless of what the provider actually holds. After any remount the picker reads "GPT-5.5 / Low" while requests still go out with whatever was really selected.

    FixLift the selection into useAIChat and make the picker fully controlled.

    • ModelPicker.tsx:116-130
    • useAIChat.tsx:33-36
  • Wrong

    Enter has no guards

    The Enter handler checks neither canSend nor isTurning. Enter mid-stream starts a second concurrent turn against the same thread; Enter on whitespace clears the box without sending.

    FixGate on both, and only clear the value once the send is actually accepted.

    • AITextBox.tsx:21-27
  • Wrong

    The send button is only cosmetically disabled

    When there's nothing to send the button gets primaryActionDisabled — grey fill, cursor-not-allowed — but never the actual disabled attribute. It stays clickable, focusable, and reachable by keyboard.

    FixSet disabled={!canSend && !isTurning} and let the styling follow the real state.

    • AITextBox.tsx:57-72
  • Wrong

    isTurning flips at the wrong moments

    It's set true only after queryAI resolves, so the button reads "send" for the entire initial round-trip. And the else setTurn(true) inside the stream loop re-arms it after turn/completed if any further chunk arrives.

    FixSet it before the call; clear it only on turn/completed and in the error path.

    • useAIChat.tsx:76-107
  • Rough

    An unused round-trip delays every send

    messageSend awaits loadThreadMessages(threadID) and throws the result away. It's pure added latency before the user's own message appears on screen.

    FixRemove the call.

    • useAIChat.tsx:50
  • Rough

    The shimmer restarts on every render

    motion.create(Component) runs inside the render body, producing a brand-new component type each pass. React unmounts and remounts the animated node, so the sweep restarts — visible as a stutter under streaming updates and doubled by StrictMode.

    FixHoist the motion component out of render, or memoize it on Component.

    • ai-elements/shimmer.tsx:26-28
    • main.tsx:15
  • Rough

    Debug logging left in

    Four console.log calls ship in the render path, including one that prints the selected model on every change.

    FixRemove.

Verification

There is no test suite in apps/novus, so verification is the typechecker plus a scripted manual pass. Typecheck is green today — keep it that way.

cd apps/novus && npm run typecheck && npm run lint npm run dev # with apps/server listening on localhost:2024
  • Window chrome — the window can be dragged and closed on Linux.
  • Tokens — the model dropdown animates in, has a solid background, and shows no stray white hairline ring.
  • Composer — paste ~50 lines; the box caps out and scrolls instead of clipping.
  • Stop — send, then Stop mid-stream: the shimmer disappears and no ghost message remains.
  • Delete — delete the selected thread: the row goes and the transcript clears. Delete a thread with nothing selected: the row still goes.
  • Model picker — pick GPT-5.6-Sol + High, switch threads and back: it still reads Sol / High.
  • Error path — stop the server and send: an error appears, the button returns to Send, no infinite shimmer.
  • Wide window — maximize past 1440px: composer and messages stay aligned.
  • Empty state — launch with no thread selected: the empty state shows and the composer is disabled.
  • Keyboard — Tab through sidebar → project → thread → delete → composer → picker → send. Every stop shows a visible focus ring, and the delete button appears on focus.

One thing worth deciding up front: Phase 1 rewrites how every component names its colors. It will touch nearly every cn(...) call in the app, and it does not pair well with concurrent work on the same files.

Phases 2 and 5 are independent of it and can run alongside. Phases 3, 4, and 6 should wait for Phase 1 to land.
