Implementation plan

Load projects & messages with React Query

Replace hand-rolled useState + manual .map reconciliation with the TanStack Query cache you already have installed. Data loading becomes declarative, mutations invalidate, and the copy/merge/patch state disappears.

@tanstack/react-query ^5 @trpc/tanstack-react-query ^11 node:sqlite

Why this change

The problem today

  • AISidebar.tsx copies projectsQuery.data into a local useState<Project[]> via a useEffect, fires one getThreads request per project (an N+1 waterfall), and hand-patches state after addThread with another .map.
  • useAIChat.tsx keeps a messagesByThread record in useState, manually loads messages on thread switch, and reconciles by hand.

The fix

  • Make the query cache the source of truth: useQuery for reads, useMutation + invalidateQueries for writes.
  • The .map calls used for rendering lists stay — that’s just JSX. It’s the .map-based state reconciliation that goes away.
  • Verified: ThreadService.ts already persists messages during queryAI, so invalidate-and-refetch after a stream is a safe reconciliation step.

Server: one joined query

apps/server

Add a getProjectsWithThreads procedure that returns projects with nested threads in a single round trip — this kills the N+1 waterfall. Returning the renderer’s existing thread shape means ProjectDropdown and ThreadItem need zero changes.

apps/server/appRouter.ts
getProjectsWithThreads: publicProcedure.query(() => {
  const projects = getProjects.all() as ProjectRecord[];
  const threads = getAllThreads.all() as ThreadRecord[];

  return projects.map((project) => ({
    id: project.id,
    name: project.name,
    path: project.path,
    threads: threads
      .filter((t) => t.project_id === project.id)
      .map((t) => ({
        id: t.id,
        projectId: t.project_id,
        title: t.name,
        projectPath: project.path,
      })),
  }));
}),
ℹ️

Also add a prepared statement in lightQueries.ts — SELECT * FROM threads, ordered newest-first to match the current thread ordering. Keep the old getProjects/getThreads procedures on the server; the renderer just stops calling them.

Delete the projects useState, the entire useEffect + Promise.all merge (lines 64–101), the draftCount ref and draft-thread construction (the draft id is overwritten immediately by the server response — dead code), and the setProjects(...map...) patch. Replace with:

const projectsQuery = useQuery(trpc.getProjectsWithThreads.queryOptions());
const projects = projectsQuery.data ?? [];

const addThreadMutation = useMutation(
  trpc.addThread.mutationOptions({
    onSuccess: () =>
      queryClient.invalidateQueries({
        queryKey: trpc.getProjectsWithThreads.queryKey(),
      }),

async function handleNewChat(projectId = currentThread?.projectId) {
  if (!projectId) return;
  const project = projects.find(({ id }) => id === projectId);
  if (!project) return;

  const created = await addThreadMutation.mutateAsync({
    threadName: "Untitled chat",
    projectId,
  });

  setCurrentThread({
    id: created.id,
    projectId,
    title: created.name,
    projectPath: project.path,
  });
}

Replace the local Project interface with the inferred router output type (type Project = (typeof projects)[number]) so the nested threads shape stays in sync with the server automatically.

Messages: the cache is the source of truth

useAIChat.tsx

Reads: per-thread cached query

Delete messagesByThread, loadThreadMessages, and the async body of setCurrentThread (it becomes a plain setter with the same-id guard). Replace with one query keyed by the current thread:

apps/desktop/src/renderer/context/useAIChat.tsx
import { skipToken, useQuery, useMutation } from "@tanstack/react-query";
import { trpc, trpcClient, queryClient } from "@/utils/trpc";

const messagesQuery = useQuery(
  trpc.loadMessages.queryOptions(
    currentThread ? { threadID: currentThread.id } : skipToken,
  ),
);
const messages = messagesQuery.data ?? [];

Per-thread caching comes for free: switching back to a thread renders instantly from cache, then background-refetches. The server’s loadMessages already returns { id, text, role } — the exact ChatMessage shape, so no mapping is needed.

Writes: stream into the cache

messageSend streams chunks into the cache with setQueryData instead of local state, then reconciles with the persisted server rows at the end of the turn:

apps/desktop/src/renderer/context/useAIChat.tsx
async function messageSend(value: string) {
  const text = value.trim();
  if (!text || !currentThread) return;

  const threadID = currentThread.id;
  // capture the key up front — a mid-stream thread switch keeps writing to the right entry
  const messagesKey = trpc.loadMessages.queryKey({ threadID });
  const assistantMessageID = crypto.randomUUID();

  // don't let an in-flight refetch overwrite the optimistic rows
  await queryClient.cancelQueries({ queryKey: messagesKey });

  queryClient.setQueryData(messagesKey, (old = []) => [
    ...old,
    { id: crypto.randomUUID(), text, role: "user" as const },
    { id: assistantMessageID, text: "", role: "assistant" as const },
  ]);

  setTurn(true);
  try {
    const streamChat = await trpcClient.queryAI.query({ threadID, message: text, model });

    for await (const chunk of streamChat) {
      if (chunk.type === "item.completed" && chunk.item.type === "agent_message") {
        const responseText = chunk.item.text;
        queryClient.setQueryData(messagesKey, (old = []) =>
          old.map((m) =>
            m.id === assistantMessageID ? { ...m, text: m.text + responseText } : m,
          ),
        );
      }
    }
  } finally {
    setTurn(false); // also clears the spinner on stream errors
  }

  // DB already holds both rows (ThreadService persists them) — reconcile IDs/rows
  await queryClient.invalidateQueries(trpc.loadMessages.queryFilter({ threadID }));

  const threadTitle = await generateTitleMutation.mutateAsync({ id: threadID, message: text });
  // keep the existing validity checks, then update the current thread's title
  setThread((cur) => (cur?.id === threadTitle.id ? { ...cur, title: threadTitle.name } : cur));
}

The finally-based setTurn also fixes the stale-closure if (!isTurning) setTurn(true) bug in the current loop.

Mutations with invalidation

createProject and title generation become mutations that invalidate the sidebar query — the two manual projectsQuery.refetch() calls go away:

apps/desktop/src/renderer/context/useAIChat.tsx
const addProjectMutation = useMutation(
  trpc.addProject.mutationOptions({
    onSuccess: () =>
      queryClient.invalidateQueries({ queryKey: trpc.getProjectsWithThreads.queryKey() }),
  }),
);

const generateTitleMutation = useMutation(
  trpc.generateThreadMessage.mutationOptions({
    onSuccess: () =>
      queryClient.invalidateQueries({ queryKey: trpc.getProjectsWithThreads.queryKey() }),
  }),
);

The public AIContext type is unchanged, so ChatMessages.tsx, AITextBox.tsx, ThreadItem.tsx, and ModelPicker.tsx need no edits.

Query defaults (optional polish)

utils/trpc.ts

A small staleTime prevents a window-refocus refetch of loadMessages from clobbering an in-flight optimistic stream (the assistant text isn’t in the DB until item.completed):

apps/desktop/src/renderer/utils/trpc.ts
export const queryClient = new QueryClient({
  defaultOptions: {
    queries: { staleTime: 5_000, retry: 1 },
  },
});
⚠️

Known cosmetic caveat: the server stores each completed agent_message as a separate row while the UI concatenates them into one bubble, so after the end-of-turn refetch a multi-item response may split into multiple assistant bubbles (matching what the DB actually stores). Acceptable for now; fixable later server-side.
