One atom per thread

Each thread gets its own Jotai atom holding its messages and isStreaming. useThreads decides which thread is open; the atom holds what’s in it.

useThreads()Which thread is open. Creates new threads.
currentThread.id
threadAtom(id){ messages, isStreaming, loaded } for that one thread.
useChatSession()
ChatView, ComposerRender messages, send, stop.

If you switch threads mid-reply, the stream keeps writing into the original thread’s atom, so text can never leak into the thread you switched to.

The problem to fix first

The app currently has two separate “current thread” values that don’t stay in sync:

WhereWritten byRead by
useThreadsnewThread() onlyuseChatSession
useAIChatClicking a thread, AISidebarTop bar, Composer, sidebar

Clicking an existing thread only updates the useAIChat copy, so useChatSession would show the wrong thread. The plan makes useThreads the only owner of selection. useThreads.tsx itself doesn’t change.

The code doesn’t compile right now: useChatSession.tsx:18 has a syntax error, and Composer calls messageSend, which useAIChat no longer has. These changes fix both.

How to check it works

  • npx tsc --noEmit -p apps/novus passes.
  • Clicking a thread in the sidebar loads its messages.
  • Sending a message streams the reply into the chat.
  • Switching threads mid-reply leaves the other thread untouched.
  • Stopping a turn turns the stop button back into send.
