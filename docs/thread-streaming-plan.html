Per-thread streaming plan

Move streamed text out of the shared chat context into a per-thread store. Thread A keeps streaming while you open B, and each view re-renders only for its own thread. Proposal only; no app code has changed.

What happens today

  • context/useAIChat.tsx keeps Record<string, ChatMessage[]>. Every delta copies the record, runs .map() over the thread history and re-renders every consumer.
  • isTurning is global and flips on for every non-turn/completed event, so threads cannot report separate status.
  • setCurrentThread always reloads and replaces the array, so switching back mid-stream can overwrite live text with stale server history.
  • lightThread.ts never sets turnId, so stopTurn() always throws.
  • The server persists only final_answer messages. The frontend AIEvent type knows only the delta and turn/completed, with no IDs or outcome.
  • AISidebar.tsx keeps its own project state beside the React Query cache.

Decided approved

  • No .map, history scan or all-thread record copy per chunk.
  • A keeps streaming while B is selected; B can start while A runs.
  • Partial text stays in memory after error, stop and thread switches.
  • Per-thread store with per-thread listeners and cached immutable snapshots.
  • Switching or unmounting a view unsubscribes; it never aborts a stream.
  • No token text in shared context.
  • Per-thread status; no global isTurning.

Unresolved needs a call

  • Second send on a streaming thread: block, queue, steer or run concurrently. The plan assumes none.
  • How tool calls and reasoning group under a turn. Today all agentMessage deltas join into one response; the plan keeps that.

Deferred later

  • Persisting partial text and recovering it after reload.
  • Reconciling server history IDs with optimistic frontend IDs.

Implementation phases

Each phase leaves the app building. Code is a sketch.

1Store and boundariesPer-thread store read via useSyncExternalStore›

A plain TypeScript store, created once above the chat view so it outlives the mounted thread. Entries are mutable internally; React sees only frozen snapshots, and published arrays and messages are never mutated.

type ThreadStatus = "idle" | "loading" | "streaming"
  | "completed" | "interrupted" | "failed";

type ThreadEntry = {
  history: readonly ChatMessage[];        // committed; replaced only on commit/hydrate
  live: { requestId: string; turnId: string | null; text: string } | null;
  retained: readonly ChatMessage[]; // partial drafts; append only when settling
  status: ThreadStatus;
  error: string | null;
  hydration: "none" | "pending" | "done";
  snapshot: ThreadSnapshot | null;   // cache; null = needs rebuild
};

class ThreadChatStore {
  private entries = new Map<string, ThreadEntry>();
  private listeners = new Map<string, Set<() => void>>();

  subscribe(threadId: string, fn: () => void) {
    let set = this.listeners.get(threadId);
    if (!set) this.listeners.set(threadId, (set = new Set()));
    set.add(fn);
    return () => { set!.delete(fn); if (!set!.size) this.listeners.delete(threadId); };
  }

  getSnapshot(threadId: string): ThreadSnapshot {
    const e = this.entries.get(threadId);
    if (!e) return EMPTY_SNAPSHOT;               // shared frozen constant
    return (e.snapshot ??= Object.freeze({
      history: e.history, live: e.live?.text ?? null,
      retained: e.retained, status: e.status, error: e.error,
    }));
  }

  appendDelta(threadId: string, requestId: string, delta: string) {
    const e = this.entries.get(threadId);       // direct lookup, no scan
    if (!e?.live || e.live.requestId !== requestId) return;  // stale stream
    e.live.text += delta;
    e.snapshot = null;                           // new object next read
    this.emit(threadId);                         // only this thread's listeners
  }
}
  • The snapshot reference is stable between changes, as useSyncExternalStore requires; a change builds a new one.
  • Deltas never touch history, so ChatMessages can memoize it and re-render only the live block.
  • Per chunk: one Map lookup, one concat, one small object, one listener call. The live block still re-renders, but history-sized and thread-count-sized work is gone.
2Stream lifecycleOne service owns each stream›

ThreadStreamService starts queries and writes only through the threadId and fresh requestId it captured, so selection can change freely.

async send(threadId, text, settings) {
  const requestId = crypto.randomUUID();
  store.beginTurn(threadId, requestId, userMessage(text)); // status: streaming
  let outcome: ThreadStatus = "failed";
  try {
    const stream = await trpcClient.queryAI.query({ threadID: threadId, ... });
    for await (const ev of stream) {
      switch (ev.method) {
        case "turn/started":   store.setTurnId(threadId, requestId, ev.params.turn.id); break;
        case "item/agentMessage/delta":
                               store.appendDelta(threadId, requestId, ev.params.delta); break;
        case "turn/completed": outcome = ev.params.turn.status; break; // completed | interrupted | failed
      }
    }
    // EOF without turn/completed keeps outcome "failed" with a clear message
  } catch (err) {
    outcome = "failed"; store.setError(threadId, requestId, err);   // startup or transport
  } finally {
    store.settle(threadId, requestId, outcome);
  }
}
  • settle on completed appends the assistant message to history once and clears live. History changes only on a user message, completion or hydration, never on a delta.
  • On interrupted or failed, partial text is appended to retained, an immutable list of drafts. Drafts stay visible outside history, so the next query does not erase them. Render history, drafts and live text in send order using a per-turn sequence; the request ID serves as draft identity for now.
  • Every write checks requestId, so late events from an older request are dropped.
  • Title fetch and ["threads", projectId] invalidation run after settle, keyed by the captured thread.
  • Hydration: load history once per thread, deduped by an in-flight promise. If the entry already has live, retained or uncommitted messages, skip the overwrite. This avoids ID matching for now.
3Hooks and consumersSplit the context by change frequency›
useProjects()
React Query: fetch, create, invalidate
useThreads(projectId)
Query key per project; create, delete, rename
useChatSession()
Selected thread ID, model, reasoning, access
useAIChat(threadId)
Snapshot subscription plus send and stop
  • useChatSession holds only the selected thread ID. Title and project come from the thread query cache. It changes on user actions, never per token.
  • useAIChat(threadId) passes stable callbacks subscribe = listener => store.subscribe(threadId, listener) and getSnapshot = () => store.getSnapshot(threadId) to useSyncExternalStore and exposes send and stop for that thread. Unmounting removes the listener; the stream continues.
  • ChatMessages.tsx renders memoized history, retained drafts and one live block. Auto-scroll must also track live length.
  • AISidebar.tsx switches to useProjects and a useThreads per project row. ThreadItem.tsx can show a streaming dot from a status-only subscription.
  • Composer.tsx, ModelPicker.tsx, AccessPicker.tsx and AIWindow.tsx switch to the new hooks. AiChatProvider becomes the provider for the store, service and session.
4Cancellation and event typesMake Stop work and type the events we read›

Stop fails because turnId is never assigned. Server fix:

// apps/server/lightThread.ts, inside sendQueryStream
for await (const event of this.codexInstance.streamTurn({...})) {
  if (event.method === "turn/started") this.turnId = event.params.turn.id;
  yield event;
  if (event.method === "turn/completed"
      && event.params.turn.id === this.turnId) this.turnId = null;
}
// plus: clear in finally only if this.turnId still belongs to this call
  • The generated types in packages/codex-protocol already carry a Turn with id, status and error on start/complete, and turnId and itemId on deltas.
  • Widen AIEvent to those three events using the generated types. The store ignores other events.
  • stop(threadId) calls stopTurn; status settles from the stream's interrupted event, not the stop response.
  • The server keeps one turnId per thread, so same-thread overlap also affects stop (see Unresolved).
5ValidationStore tests, typecheck, build›

Store unit tests

  • Deltas on A notify only A; B's snapshot is unchanged.
  • getSnapshot is stable between changes and new after; old snapshots stay frozen.
  • Interleaved A and B streams survive selection switches intact.
  • Hydration never overwrites a live stream and runs once per thread.
  • Completion commits exactly one assistant message.
  • Startup error, transport error, EOF without turn/completed and interrupted all keep partial text.
  • Stale requestIds cannot write; stop targets the right thread.
  • The delta path never maps history or copies the entries Map.

Checks

  • Frontend and server typecheck; frontend build.
  • Manual: stream two threads, switch both ways, stop each.
