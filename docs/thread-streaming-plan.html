Per-thread streaming plan

Move streamed text out of the shared chat context into one zustand store per thread. A keeps streaming while you view B, and each view re-renders only for its own thread. Proposal only; no app code has changed.

What happens today

  • context/useAIChat.tsx holds Record<string, ChatMessage[]>. Each delta copies it, maps the thread's history and re-renders every consumer.
  • isTurning is global, so threads can't show their own status.
  • setCurrentThread always reloads, so switching back mid-stream can replace live text with stale history.
  • lightThread.ts never sets turnId, so stopTurn() always throws.
  • The server saves only final_answer messages. The frontend AIEvent type knows only the delta and turn/completed, with no IDs or outcome.
  • AISidebar.tsx keeps its own project state beside React Query.

Decided approved

  • No .map, history scan or record copy per chunk.
  • A keeps streaming while B is selected; B can start while A runs.
  • Partial text stays in memory after error, stop and thread switches.
  • One zustand store per thread, read with selectors.
  • Switching or unmounting a view never stops a stream.
  • No token text in shared context.
  • Status is per thread; no global isTurning.

Unresolved needs a call

  • Second send on a streaming thread: block, queue, steer or run both? Not chosen yet.
  • How tool calls and reasoning group under a turn. For now all agentMessage deltas join into one reply.

Deferred later

  • Keeping partial text across reloads.
  • Matching server message IDs with local IDs.

Implementation phases

1Per-thread zustand storesOne vanilla store per thread, read with selectors›

Install: npm install zustand@^5 -w @novus/web (desktop already uses 5.0.14).

Each thread gets its own store in a Map. A delta updates only that store, so other threads' subscribers never run. One global store would copy the record and run every selector per chunk.

apps/web/src/lib/threadStore.ts new

export type ThreadStatus = "idle" | "streaming" | "completed" | "interrupted" | "failed";
export type SettledStatus = Exclude<ThreadStatus, "idle" | "streaming">;

export type ThreadState = {
  history: readonly ChatMessage[]; // replaced only on send, settle and hydrate
  live: { requestId: string; text: string } | null;
  status: ThreadStatus;
  error: string | null;
  hydrated: boolean;
};

const stores = new Map<string, StoreApi<ThreadState>>();

// ... getThreadStore(id): get or create the store
// ... useThread(id, selector): useStore on that store
// ... hydrate(id): load history once; shares an in-flight request
// ... beginTurn(id, requestId, text): add the user message, live = "", status "streaming"

export function appendDelta(threadId: string, requestId: string, delta: string) {
  const store = getThreadStore(threadId);
  const { live } = store.getState();
  if (live?.requestId !== requestId) return; // stale stream
  store.setState({ live: { requestId, text: live.text + delta } }); // history untouched
}

export function settle(threadId: string, requestId: string, status: SettledStatus, error: string | null) {
  getThreadStore(threadId).setState((s) => {
    if (s.live?.requestId !== requestId) return s; // same object: no notify
    const reply: ChatMessage = {
      id: requestId,
      role: "assistant",
      text: s.live.text,
      interrupted: status !== "completed",
    };
    const keep = status === "completed" || reply.text.length > 0;
    return { history: keep ? [...s.history, reply] : s.history, live: null, status, error };
  });
}
  • Per chunk: one Map lookup, one string join, one small object. history keeps its reference.
  • On stop or failure, partial text joins history once, marked interrupted.
  • Returning s skips the notify, so stale settles do nothing.
2Stream lifecyclePlain functions that own a stream from send to settle›

Each stream writes through its captured threadId and requestId, so switching threads never touches it.

apps/web/src/lib/threadStream.ts new

export async function sendMessage(threadId: string, text: string, mode: "build" | "plan") {
  const store = getThreadStore(threadId);
  try {
    await hydrate(threadId);
  } catch (err) {
    store.setState({ status: "failed", error: errorMessage(err) });
    return;
  }
  // Interim guard; the same-thread overlap policy is still open.
  if (store.getState().status === "streaming") return;

  const { model, access } = useSession.getState(); // captured for this turn
  const requestId = crypto.randomUUID();
  beginTurn(threadId, requestId, text);

  let status: SettledStatus = "failed";
  let error: string | null = "Stream ended before turn/completed";
  try {
    const stream = await trpcClient.queryAI.query({ threadID: threadId, message: text, model, mode, access });
    for await (const event of stream) {
      if (event.method === "item/agentMessage/delta") {
        appendDelta(threadId, requestId, event.params.delta);
      } else if (event.method === "turn/completed") {
        const { turn } = event.params;
        status = turn.status === "inProgress" ? "failed" : turn.status;
        error = turn.error?.message ?? null;
      }
    }
  } catch (err) {
    status = "failed";
    error = errorMessage(err);
  } finally {
    settle(threadId, requestId, status, error);
  }
  // ... refresh the title, invalidate ["projects"]
}

// ... stopTurn(id): call trpcClient.stopTurn; status settles from turn/completed ("interrupted")
  • EOF without turn/completed settles as failed and keeps partial text.
  • Hydration runs before the first write, so server history can't overwrite local messages.

for await (const event of this.codexInstance.streamTurn({ ... })) {

5ValidationStore tests, typecheck, build›

Store tests (web needs a runner, such as vitest)

  • Deltas on A notify only A; B's state is unchanged.
  • appendDelta keeps the history reference.
  • Interleaved A and B streams survive switching.
  • Hydration runs once per thread, before the first local write.
  • Completion adds exactly one assistant message.
  • Startup error, transport error, EOF and interrupted keep partial text, marked interrupted: true.
  • Stale requestIds can't write or settle.

Checks

  • npm run typecheck and npm run web:build.
  • Manual: stream two threads, switch both ways, stop each.

Review: DeepSeek V4.1 Flash fix before implementing

Confirmed: store isolation, hydration order, concurrent A/B streaming and in-memory partial text.

  • Stop race. Stop before turn/started throws (turnId is null). Queue it on the server until the ID arrives.
  • Server cleanup. In phase 4, clear turnId in a finally so errors and disconnects don't leave it stale.
  • Hook boundaries. Keep useProjects, useThreads, useChatSession and useAIChat(threadId) as thin wrappers over the stores and React Query.
  • Message identity. Joining all deltas ignores itemId, so commentary and the final answer merge, and live text can differ from saved history (only final_answer is saved). Key live text by itemId, or show only final answers.
  • Model picker. ModelPicker has its own state. Read the model from useSession so the shown model is the one sent.
