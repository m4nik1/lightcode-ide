Refactor proposal / 02 · TanStack Query

Less in the context.
Every thread independent.

TanStack Query stores thread messages and status. Context supplies a stable runtime that loads history and updates the cache while streams continue through navigation.

React + contextSelection, global settings, runtime access
TanStack QueryMessages, status, reactive cache
Runtime → backendStream coordination, execution, persistence
Agreed scope: concurrent turns across threads, continued streaming during navigation, and global model/access settings. Same-thread queueing and recovery after closing the app are deferred.

These are design excerpts, not a complete patch. Imports, supporting helpers, and existing layout are abbreviated. Function names describe the proposed interface; the app source is unchanged. Styling uses shadcn’s restrained zinc palette, borders, spacing, and controls in standalone HTML.

02New

Coordinate streams; write to QueryClient

apps/novus/src/chat/chatRuntime.ts

TanStack Query becomes the only store for renderable chat state. The runtime keeps only active-operation guards, pending loads and cancellation handles. It loads server history through fetchQuery, then writes immutable snapshots with setQueryData. No custom subscribe/getSnapshot implementation remains.

Proposed code Illustrative excerpt
export interface ChatRuntime {
  loadThread(id: string): Promise<void>;
  sendMessage(id: string, text: string,
    options: SendOptions): Promise<void>;
  stopTurn(id: string): Promise<void>;
}

// Inside createChatRuntime(queryClient, transport):
function patch(id: string, change: Partial<ThreadSnapshot>) {
  queryClient.setQueryData<ThreadSnapshot>(chatKeys.state(id),
    old => ({ ...(old ?? EMPTY_THREAD), ...change }));
}

// loadThread deduplicates callers using a pending-load map.
// Return immediately when the live snapshot's history is ready.
patch(id, { history: "loading", error: null });
try {
  const messages = await queryClient.fetchQuery({
    queryKey: chatKeys.history(id),
    queryFn: () => transport.loadMessages(id),
    staleTime: Infinity,
    retry: false,
  });
  patch(id, { messages, history: "ready" });
} catch (error) {
  patch(id, { history: "error", error: String(error) });
  throw error;
}

// sendMessage acquires its per-thread guard before any await.
// Capture settings, mark starting, then await loadThread(id).
// Only then append optimistic messages and consume the stream.
queryClient.setQueryData<ThreadSnapshot>(chatKeys.state(id), old =>
  old ? { ...old, messages: old.messages.map(message =>
    message.id === assistantId
      ? { ...message, text: message.text + delta }
      : message) } : old);
// Catch errors and reset turn status in finally.
// Unmounting a component does not cancel this async operation.
03New

Observe the cache with useQuery

apps/novus/src/chat/useThreadChat.ts

Read the runtime from context and subscribe to its thread snapshot using useQuery. This is intentionally a cache-only query: enabled:false prevents automatic fetching, but cache writes still update subscribers. A separate history query performs backend fetching. The hook exposes only the snapshot, not refetch.

Proposed code Illustrative excerpt
export function useThreadChat(id: string | null) {
  const runtime = useChatRuntime();
  const { data } = useQuery<ThreadSnapshot>({
    queryKey: chatKeys.state(id),
    enabled: false,
    gcTime: Infinity,
  });

  useEffect(() => {
    if (id) void runtime.loadThread(id).catch(() => {});
    // No stream cancellation on screen cleanup.
  }, [runtime, id]);

  return data ?? EMPTY_THREAD;
}
// TanStack Query handles subscriptions; useSyncExternalStore
// and the custom listener collection are removed.

09Edit

Send and Stop follow selection

apps/novus/src/components/Composer.tsx

Use this thread’s lifecycle for controls. Starting counts as busy, closing the window for duplicate sends. The runtime remembers an early Stop request until the backend turn is interruptible. Same-thread queueing remains deferred.

Proposed code Illustrative excerpt
const { currentThread, messageSend, stopTurn } = useAIChat();
const { turn, error } = useThreadChat(currentThread?.id ?? null);
const isTurning = turn !== "idle";

async function handleSend() {
  if (!currentThread) return;
  try {
    if (isTurning) {
      await stopTurn();
      return;
    }
    const text = value.trim();
    if (!text) return;
    setValue("");
    await messageSend(text, mode);
  } catch {
    // The runtime exposes the failure through this thread's error.
  }
}
// Render error next to the composer with role="alert".

13Fix

Make Stop reach the active turn

apps/server/lightThread.ts

Capture the ID from turn/started before yielding the event, and clear it in finally. Supply a sandbox policy per send; the policy mapper must explicitly preserve the project’s network and writable-root settings.

Proposed code Illustrative excerpt
try {
  for await (const event of this.codexInstance.streamTurn({
    threadId: this.id,
    model,
    effort: thinking,
    input,
    sandboxPolicy: toSandboxPolicy(access, projectPolicy),
  })) {
    if (event.method === "turn/started") {
      this.turnId = event.params.turn.id;
    }
    yield event;
  }
} finally {
  this.turnId = null;
}
// Existing stopTurn can now interrupt a known active turn.
// toSandboxPolicy maps access modes to the protocol union.

16New

Cache keys and retention

apps/novus/src/chat/chatQueries.ts

Keep fetched history separate from the live snapshot so a history fetch cannot overwrite streamed text. Live snapshots stay in memory for this app session, even without observers. This trades bounded cache eviction for navigation continuity; deletion explicitly removes both keys after stopping outstanding work.

Proposed code Illustrative excerpt
export const chatKeys = {
  state: (id: string | null) => ["chat", "state", id] as const,
  history: (id: string) => ["chat", "history", id] as const,
};

export function configureChatQueries(client: QueryClient) {
  client.setQueryDefaults(["chat", "state"], {
    gcTime: Infinity,
    staleTime: Infinity,
  });
}

// History is used for initial hydration only in this proposal.
// Never invalidate/refetch it to replace a live snapshot.
// After successful deletion and settling all thread operations:
client.removeQueries({ queryKey: chatKeys.state(id), exact: true });
client.removeQueries({ queryKey: chatKeys.history(id), exact: true });
17New

Context supplies the coordinator

apps/novus/src/context/ChatRuntimeContext.tsx

Context provides the stable runtime instance, not message snapshots. useChatRuntime gives commands to hooks; useQuery supplies reactive data. Tests can provide a fresh runtime and QueryClient without changing consumers.

Proposed code Illustrative excerpt
const ChatRuntimeContext = createContext<ChatRuntime | null>(null);

export function ChatRuntimeProvider({ runtime, children }: {
  runtime: ChatRuntime;
  children: ReactNode;
}) {
  return (
    <ChatRuntimeContext.Provider value={runtime}>
      {children}
    </ChatRuntimeContext.Provider>
  );
}

export function useChatRuntime() {
  const runtime = useContext(ChatRuntimeContext);
  if (!runtime) throw new Error("ChatRuntimeProvider is required");
  return runtime;
}
