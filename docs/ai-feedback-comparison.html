Breaks today

  • Composer calls messageSend, which was removed from useAIChat.
  • useChatSession has invalid syntax: loadMessages.query({ currentThread.id }).

Adapting the plan

  • Target apps/novus (@novus/app) and ChatView.tsx, not apps/web.
  • Reuse the branch's project and thread queries.
  • Keep thread selection in one zustand session store.
  • Put the per-thread stores and stream lifecycle behind the four hooks.
  • After a title change, invalidate ["threads", projectId], not ["projects"].

Changes I would make on ai-feedback

In order; each step leaves the app building.

  1. Fix the build. Composer calls useChatSession().sendQuery instead of messageSend. Drop the broken loadMessages query; step 4 replaces it.
  2. Add zustand. npm install zustand@^5 -w @novus/app.
  3. One session store. lib/sessionStore.ts (plan phase 3). Remove the duplicate state from AiChatProvider and ThreadProvider. useThreads keeps newThread and its invalidation but selects through the store.
  4. Per-thread stores. lib/threadStore.ts (plan phase 1), replacing messagesByThread.
  5. Stream lifecycle. lib/threadStream.ts (plan phase 2). sendMessage takes the thread object so it can invalidate ["threads", thread.projectId] after settle.
  6. Thin hooks. useChatSession() reads the session store. useAIChat(threadId) returns that thread's history, live, status, send and stop. useProjects stays.
  7. Components. As in plan phase 3, with ChatView.tsx in place of ChatMessages.tsx. AIWindow drops the old providers.
  8. Events and Stop. Plan phase 4, plus the review's Stop race and cleanup fixes.
  9. Verify. npm run typecheck, npm run novus:build, then the manual check from plan phase 5.

Still open: same-thread overlap policy, and whether live text is keyed by itemId or shows only final answers.
