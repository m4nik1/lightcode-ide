Implementation plan · Novus

Manage threads by project

Keep projects and threads in React Query. Each project gets its own thread list, so adding a chat updates that list directly.

1. Give each list an address

Remove the combined projects state from AISidebar.tsx. Keep project metadata and thread rows in separate cache entries.

["projects"]            → ProjectRow[]
["threads", projectId]  → ThreadRow[]

The cache stores the data; query hooks subscribe to it. Updating a key notifies its subscribers, so there is no second project/thread copy to synchronize.

2. Preserve coordinated loading

Replace the loading effect with useQueries in the sidebar. It loads one thread query per project in parallel and keeps results in those keys. Pass each result to its project dropdown.

const projects = getProjects.data ?? [];
const threadQueries = useQueries({
  queries: projects.map((project) => ({
    queryKey: ["threads", project.id],
    queryFn: () => trpcClient.getThreads.query({
      projectID: project.id,
    }),
    staleTime: 60_000,
  })),
});

const loading = threadQueries.some((query) => query.isPending);

Use the aggregate loading state to keep a coordinated initial reveal; show errors with a retry action. Selection and title changes no longer trigger the loader. The current code already makes one query per project; HTTP batching is a separate transport concern.

3. Write to the affected project

A new useThreads.ts module owns shared query options and create/delete/title cache updates. After creation succeeds, prepend the saved row to the existing list.

// Inside createThread(project); after addThread succeeds.
const key = ["threads", project.id];
await queryClient.cancelQueries({ queryKey: key, exact: true });

queryClient.setQueryData<ThreadRow[]>(key, (rows) =>
  rows === undefined ? undefined : [
    { ...created, project_id: project.id },
    ...rows.filter((row) => row.id !== created.id),
  ],
);

if (queryClient.getQueryData(key) === undefined) {
  await queryClient.fetchQuery(threadOptions(project.id));
}

threadOptions supplies the same key and fetcher used above. Cancel stale reads before writing; if the list is absent, fetch the complete list. Return the created thread with the project's path, then select it. Surface failures and allow retry.

Deletion filters this same list after server success. Title generation updates its matching row and the selected thread, replacing projectsQuery.refetch(). Deleting the selected thread also clears selection.

Files to change

  • context/useThreads.ts — add shared query options and thread mutations.
  • sidebar/AISidebar.tsx — remove nested state, reload effect and unused draft IDs; load via queries and select created chats.
  • sidebar/ProjectDropdown.tsx and ThreadItem.tsx — accept separate project/thread data and route deletion through the shared module.
  • context/useAIChat.tsx — update cached titles; allow clearing selection. Use the existing useProjects hook for project creation.

Verify the result

  1. Load multiple projects: correct threads, loading, empty and error states.
  2. Create, rename and delete: only the target project's cached list changes; selection stays correct.
  3. Switch chats: no thread-list requests caused by selection. Check creation during loading and rapid repeated creates.
  4. Run the Novus typecheck and relevant lint checks after implementation.

Expected gain: no project-array reconstruction on thread writes and no all-project reload on chat selection. Immutable updates still copy one project's thread list; they are not O(1), and other components may still render.
