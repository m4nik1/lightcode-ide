Daytona integration / Worker architecture

One focused worker per project sandbox.

A small, secure bridge that runs beside the project, owns Codex, and streams work back to the main Lightcode server.

The simple model

The parent server remains the control plane. Each Daytona sandbox gets a lightweight worker with direct access to that project's files.

Clear ownership

P

Parent server

  • Users and authentication
  • Projects, threads, and message history
  • Daytona sandbox lifecycle
  • Repository configuration
  • Worker discovery and request routing
W

Sandbox worker

  • Starts and owns Codex app-server
  • Accesses /workspace/project
  • Starts, resumes, and interrupts turns
  • Streams Codex notifications upstream
  • Reports health and runtime errors
Keep the worker disposable.

It should not own a database, user state, or Daytona orchestration. Durable state stays with the parent.

Where the worker runs

The worker runs as a long-lived Node.js process inside the Daytona sandbox. Daytona may implement that sandbox with containers, microVMs, or another isolated runtime. Lightcode should use the sandbox abstraction rather than depend on the underlying technology.

How it starts

Build a reusable sandbox image

Include Node.js, Git, the worker bundle, and the pinned Codex package. This avoids reinstalling the agent for every project.

Create one sandbox per project

The parent asks Daytona to create a sandbox from that image and saves the returned sandbox ID.

Clone into the workspace

Clone the project into /workspace/project, using a short-lived Git credential for private repositories.

Inject runtime secrets

Pass the parent URL, worker identity, short-lived worker token, and OpenAI credentials at process start. Do not bake secrets into the image.

Launch and supervise

Start the worker as the sandbox service or entrypoint so it restarts when the sandbox wakes or the process exits unexpectedly.

Why not put the worker beside the parent?

Codex executes commands and edits files relative to its own machine. Running the worker inside Daytona ensures every Codex action is isolated with the correct project and toolchain.

Worker connection

Let the worker open one outbound WebSocket to the deployed parent. This avoids exposing a public endpoint for every sandbox.

Parent: accept the worker connection

This example uses the Node ws package in the parent server. Authenticate during the HTTP upgrade, then register the live socket by project.

import { WebSocketServer } from "ws";

const workerSockets = new WebSocketServer({ noServer: true });

httpServer.on("upgrade", async (request, socket, head) => {
  const url = new URL(request.url ?? "/", "https://api.lightcode.dev");
  if (url.pathname !== "/workers/connect") return socket.destroy();

  const token = request.headers.authorization?.replace("Bearer ", "");
  const identity = await workerTokens.verify(token);
  if (!identity) return socket.destroy();

  workerSockets.handleUpgrade(request, socket, head, (webSocket) => {
    workerManager.register({
      workerId: identity.workerId,
      projectId: identity.projectId,
      socket: webSocket,
      connectedAt: Date.now(),
      lastSeenAt: Date.now()
    });

    webSocket.on("message", (data) => {
      workerManager.handleMessage(identity.workerId, data.toString());
    });

    webSocket.on("close", () => {
      workerManager.disconnect(identity.workerId, webSocket);
    });
  });
});

Worker: connect from the Daytona sandbox

The worker initiates the connection, announces readiness, and receives commands over the same socket.

import WebSocket from "ws";
import { CodexAppServerClient } from "@lightcode/codex-protocol";

const codex = new CodexAppServerClient({
  clientInfo: {
    name: "lightcode-worker",
    title: "Lightcode Worker",
    version: "0.1.0"
  }
});

await codex.connect(); // Starts Codex inside this Daytona sandbox.

const socket = new WebSocket(process.env.LIGHTCODE_SERVER_URL!, {
  headers: {
    authorization: `Bearer ${process.env.LIGHTCODE_WORKER_TOKEN}`
  }
});

socket.on("open", () => {
  socket.send(JSON.stringify({
    method: "worker.ready",
    params: {
      workerId: process.env.LIGHTCODE_WORKER_ID,
      projectPath: process.env.LIGHTCODE_PROJECT_PATH,
      version: "0.1.0"
    }
  }));
});

socket.on("message", async (raw) => {
  const request = WorkerRequestSchema.parse(JSON.parse(raw.toString()));

  if (request.method === "thread.start") {
    const result = await codex.startThread({
      cwd: process.env.LIGHTCODE_PROJECT_PATH!,
      sandbox: request.params.access,
      approvalPolicy: "never"
    });

    socket.send(JSON.stringify({
      id: request.id,
      result: { codexThreadId: result.thread.id }
    }));
  }
});

Recovery rules

R

Reconnect

The worker reconnects with exponential backoff after a dropped WebSocket or parent restart.

S

Resume

After a worker restart, resume Codex using the persisted remote thread ID.

LOCK

Serialize

Allow only one active turn per Codex thread to avoid conflicting writes and events.

!

Fail clearly

If resume fails, report the failure instead of silently creating an unrelated thread.

Connection registry example

The parent keeps one active connection per worker. A newer authenticated connection replaces an older one, which makes reconnects deterministic.

type ConnectedWorker = {
  workerId: string;
  projectId: string;
  socket: WebSocket;
  connectedAt: number;
  lastSeenAt: number;
};

class WorkerManager {
  private workers = new Map<string, ConnectedWorker>();
  private pending = new Map<string, {
    resolve(value: unknown): void;
    reject(error: Error): void;
    timer: NodeJS.Timeout;
  }>();

  register(worker: ConnectedWorker) {
    this.workers.get(worker.workerId)?.socket.close(4001, "Replaced");
    this.workers.set(worker.workerId, worker);
  }

  disconnect(workerId: string, socket: WebSocket) {
    if (this.workers.get(workerId)?.socket === socket) {
      this.workers.delete(workerId);
    }
  }

  getForProject(projectId: string) {
    const worker = [...this.workers.values()]
      .find((candidate) => candidate.projectId === projectId);

    if (!worker) throw new Error("Project worker is offline");
    return worker;
  }
}

Correlated requests

Each parent command returns a promise. The worker replies with the same ID, while turn notifications are emitted as separate events with that request ID.

request(workerId: string, method: string, params: unknown) {
  const id = crypto.randomUUID();
  const worker = this.workers.get(workerId);
  if (!worker) throw new Error("Worker is offline");

  return new Promise((resolve, reject) => {
    const timer = setTimeout(() => {
      this.pending.delete(id);
      reject(new Error(`${method} timed out`));
    }, 30_000);

    this.pending.set(id, { resolve, reject, timer });
    worker.socket.send(JSON.stringify({ id, method, params }));
  });
}

Heartbeat policy

Every 15 seconds

Parent sends ping, or uses WebSocket protocol ping frames.

After 45 seconds

No response means the connection is stale. Close it and mark the worker offline.

On reconnect

Worker reports its version, project ID, active turns, and Codex readiness.

Provisioning service example

async function ensureProjectWorker(projectId: string) {
  const project = await projects.get(projectId);
  const connected = workerManager.findForProject(projectId);
  if (connected) return connected;

  await projects.setStatus(projectId, "starting");

  const sandbox = project.daytonaSandboxId
    ? await daytona.start(project.daytonaSandboxId)
    : await daytona.create({ projectId });

  if (!project.daytonaSandboxId) {
    await sandbox.git.clone(project.repositoryUrl, "/workspace/project");
    await projects.attachSandbox(projectId, sandbox.id);
  }

  const token = await workerTokens.issue({ projectId, expiresIn: "10m" });
  await sandbox.process.executeCommand(
    "node /opt/lightcode-worker/dist/index.js",
    {
      LIGHTCODE_WORKER_TOKEN: token,
      LIGHTCODE_PROJECT_PATH: "/workspace/project"
    }
  );

  const worker = await workerManager.waitForProject(projectId, 30_000);
  await projects.setStatus(projectId, "ready");
  return worker;
}
Adapt the process calls to the installed Daytona SDK version.

The key contract is create or wake, clone only when needed, start with a short-lived token, then wait for an authenticated worker.ready.

Worker command handling example

socket.on("message", async (raw) => {
  const request = WorkerRequestSchema.parse(JSON.parse(raw.toString()));

  try {
    if (request.method === "thread.start") {
      const result = await codex.startThread({
        cwd: process.env.LIGHTCODE_PROJECT_PATH!,
        sandbox: request.params.access,
        approvalPolicy: "never"
      });
      reply(request.id, result);
    }

    if (request.method === "turn.start") {
      for await (const event of codex.streamTurn(request.params)) {
        emit("turn.event", { requestId: request.id, event });
      }
      reply(request.id, { completed: true });
    }
  } catch (error) {
    fail(request.id, normalizeError(error));
  }
});

What to monitor

Availability

Connected workers, ready sandboxes, reconnect count, and heartbeat age.

Performance

Provisioning time, worker-ready time, prompt latency, and turn duration.

Failures

Request timeouts, Codex exits, resume failures, and sandbox API errors.

Implementation path

PROTOTYPE

Local worker prototype

Run parent and worker as separate local processes. Prove authenticated commands, event streaming, and interruption over WebSocket.

EXTRACT

Extract Codex execution

Move Codex ownership from the parent ThreadService into the worker's CodexRuntime.

ROUTE

Add worker routing

Map projects to connected workers while keeping tRPC, persistence, and UI streaming in the parent.

DAYTONA

Integrate Daytona

Create a sandbox, clone the repository, start the worker, and wait for worker.ready.

HARDEN

Harden recovery

Add token rotation, timeouts, reconnects, sandbox wake-up, thread resume, and cleanup.

MVP boundary

One parent, one worker per sandbox, one Codex process per worker, and one outbound WebSocket per worker. Add queues and service discovery only when scale demands them.
