Core idea

Use async function* in your tRPC procedure and yield JSON-serializable chunks as Codex events arrive.

01 · Mental model

Streaming is just yielding chunks over time.

On the server, the Codex SDK gives you an async stream of events. Your tRPC procedure loops over those events and decides what to send to the client.

1
Codex SDK produces events

thread.runStreamed(prompt) returns an object containing an async event stream.

2
Server loops over the stream

for await (const event of events) receives each Codex event as it becomes available.

3
tRPC sends each yielded value

Every yield pushes one JSON chunk to the client through the streaming transport.

02 · Server implementation

Forward Codex events through tRPC.

This version streams structured Codex events. It is the most flexible approach because the client can react differently to text, tool activity, status updates, and completion.

server/routers/ai.ts 
import { z } from "zod";
import { Codex } from "@openai/codex-sdk";
import { router, protectedProcedure } from "../trpc";

const codex = new Codex();

type StreamChunk =
  | {
      type: "codex_event";
      eventType: string;
      event: unknown;
    }
  | {
      type: "done";
    };

export const aiRouter = router({
  streamCodexPrompt: protectedProcedure
    .input(
      z.object({
        prompt: z.string().min(1),
        threadId: z.string().optional(),
      }),
    )
    .query(async function* ({ input }): AsyncGenerator<StreamChunk> {
      const thread = input.threadId
        ? codex.resumeThread(input.threadId)
        : codex.startThread({
            workingDirectory: process.cwd(),

            // Useful during local development if the cwd is not a git repo.
            // Remove this when you want stricter repo safety.
            skipGitRepoCheck: true,
          });

      const { events } = await thread.runStreamed(input.prompt);

      for await (const event of events) {
        yield {
          type: "codex_event",
          eventType: event.type,
          event,
        };

        if (event.type === "turn.completed") {
          yield { type: "done" };
        }
      }
    }),
});
03 · What yield does

yield sends one streamed value.

yield does not automatically mean “stream text.” It sends whatever value you place after it.

Minimal async generator 
.query(async function* () {
  yield "hello";
  yield " ";
  yield "world";
})

The client receives these as incremental stream chunks:

Client-side accumulated result 
["hello", " ", "world"]
yield value

Sends one value immediately and keeps the generator alive for more chunks.

return value

Ends the generator and sends no more streamed chunks after that point.

04 · Text-only stream

Transform events before yielding.

If your UI only needs assistant text, extract text from Codex events on the server and yield a smaller shape. The exact extraction logic depends on the event shapes you want to support.

Server-side text chunks 
streamCodexPrompt: protectedProcedure
  .input(
    z.object({
      prompt: z.string().min(1),
    }),
  )
  .query(async function* ({ input }) {
    const thread = codex.startThread({
      workingDirectory: process.cwd(),
      skipGitRepoCheck: true,
    });

    const { events } = await thread.runStreamed(input.prompt);

    for await (const event of events) {
      if (event.type === "item.completed") {
        const item = event.item as any;

        const text =
          typeof item?.text === "string"
            ? item.text
            : typeof item?.content === "string"
              ? item.content
              : "";

        if (text) {
          yield {
            type: "text",
            text,
          };
        }
      }

      if (event.type === "turn.completed") {
        yield {
          type: "done",
        };
      }
    }
  });

That produces simple chunks like this:

Streamed result shape 
[
  { type: "text", text: "Here is" },
  { type: "text", text: " the answer..." },
  { type: "done" }
]
05 · Design choice

Choose between raw events and text chunks.

Most flexible

Yield Codex events

Best when the client needs to display rich status: assistant messages, tool calls, file edits, progress, errors, and completion.

Raw event chunk 
yield {
  type: "codex_event",
  eventType: event.type,
  event,
};
Simpler UI

Yield text only

Best when the client only needs to append visible text to a chat bubble or output panel.

Text chunk 
yield {
  type: "text",
  text,
};
06 · Server-side gotchas

Keep the stream tRPC-native.

Do not return a Node Readable, PassThrough, or raw SSE response from the procedure. In tRPC, the procedure should return an async generator and yield JSON-serializable chunks.

Use async function*

This declares an async generator, which can pause, yield, and resume while Codex events arrive.

Yield serializable data

Stick to strings, numbers, booleans, arrays, and plain objects. Avoid streams, class instances, and functions.

Keep Codex server-side

The SDK and credentials should stay on your Node.js backend, not in browser code.

Send a done event

A final { type: "done" } chunk makes client state management easier.
