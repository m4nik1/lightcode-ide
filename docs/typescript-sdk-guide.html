Source-backed field guide

Run Codex agents from Node.js.

A practical map to @openai/codex-sdk: how it launches the CLI per turn, resumes local conversations, streams JSONL events, and safely lets an agent work in your repository.

A thin SDK over codex exec

The TypeScript SDK is not a REST client and does not keep an agent server resident. A Codex object stores launch configuration; each call to run() or consumption of runStreamed() starts a fresh local CLI process.

01

Codex

Resolves the CLI and stores global binary, URL, key, config, and environment options.

02

Thread

Holds fixed execution options and a local persisted session ID. It does not hold message history itself.

03

Turn

One CLI invocation. Buffered run() returns completed snapshots; streamed mode exposes progress.

04

Item

A typed unit of work such as an assistant message, command, file change, MCP call, or todo list.

Mental model: thread continuity comes from Codex session files and resume <thread-id>, not from a long-lived Node subprocess.

How one turn travels

The SDK converts options into CLI flags, writes the prompt to stdin, and parses one event from each stdout line.

Your processNode.js applicationCodex → Thread
→
Fresh child per turncodex exec--experimental-json
→
Agent runtimeModel + toolsworkspace / shell / MCP
stdin: raw prompt →   child process   → stdout: newline-delimited JSON events
Normalize inputStrings become the prompt. Structured text entries join with blank lines; local image paths become repeated --image flags.
Build command argumentsGlobal config is emitted first, then base URL and thread options so more specific values win.
Start or resumeThe first turn invokes codex exec; later turns add resume <id>.
Parse eventsEach stdout line is JSON.parsed and yielded. thread.started populates the thread ID.
Clean upThe child closes after the turn. Temporary structured-output files are removed in a finally block.
Streaming is lazy: await thread.runStreamed() returns a generator wrapper, but does not start the child process. Execution starts when code begins iterating events.

From zero to first turn

The published SDK includes a matching Codex CLI dependency. Existing CLI authentication and configuration are used unless you supply explicit overrides.

Terminal 
npm install @openai/codex-sdk
quickstart.ts 
import { Codex } from "@openai/codex-sdk";

const codex = new Codex();
const thread = codex.startThread({
  workingDirectory: "/path/to/project",
  sandboxMode: "read-only",
});

const result = await thread.run(
  "Explain this repository in three bullets.",
);

console.log("thread:", thread.id);
console.log("usage:", result.usage);
console.log(result.finalResponse);

What run() returns

Field Meaning
items: ThreadItem[] Only completed item snapshots, in event order.
finalResponse: string Text from the last completed agent_message; empty when none is emitted.
usage: Usage | null Usage from turn.completed. Current runtime data can be cumulative for the thread.

run() vs runStreamed()

Both execute a turn. Choose based on whether you need a collected result or live state transitions.

Method Returns Use when
thread.run(input, options?) Promise<RunResult> You can wait and only need final completed items, final text, and usage.
thread.runStreamed(input, options?) Promise<{ events: AsyncGenerator<ThreadEvent> }> You need commands, file changes, MCP progress, item updates, or custom rendering.
multi-turn.ts 
const thread = codex.startThread({
  workingDirectory: "/path/to/project",
  sandboxMode: "workspace-write",
});

const analysis = await thread.run("Diagnose the failing tests.");
console.log(analysis.finalResponse);

// Reuses the thread ID and persisted conversation history.
const implementation = await thread.run("Implement the smallest fix.");
console.log(implementation.finalResponse);
  • A new thread starts with thread.id === null; the first thread.started event sets it.
  • Thread options are fixed when the Thread is created. Only output schema and cancellation vary by turn.
  • Avoid concurrent turns on the same Thread; there is no concurrency guard around its ID or persisted state.

Stream the agent's work

Iterate the async generator to receive state transitions. Always handle terminal turn events and top-level errors.

stream.ts 
import { Codex, type ThreadEvent } from "@openai/codex-sdk";

const thread = new Codex().startThread({
  workingDirectory: "/path/to/project",
});
const { events } = await thread.runStreamed("Review the test strategy.");

for await (const event of events) {
  switch (event.type) {
    case "thread.started":
      console.log("thread", event.thread_id);
      break;
    case "item.started":
    case "item.updated":
    case "item.completed":
      console.log(event.type, event.item.type, event.item);
      break;
    case "turn.completed":
      console.log("usage", event.usage);
      break;
    case "turn.failed":
      throw new Error(event.error.message);
    case "error":
      console.error(event.message);
      break;
  }
}
Generator ownership: consume the stream to completion. If iteration stops early, generator cleanup kills the child if needed and removes temporary schema files.

Events and item types

Top-level events describe lifecycle; item payloads describe the work. Use both event.type and event.item.type as discriminants.

Event Payload / behavior
thread.started thread_id; emitted for new and resumed executions.
turn.started Signals agent processing has begun.
item.started Initial in-progress snapshot for supported work items.
item.updated Replacement snapshot as command, MCP, or todo state changes.
item.completed Terminal success/failure snapshot; the only items collected by run().
turn.completed Terminal success plus usage.
turn.failed Terminal failure with error.message.
error Unrecoverable stream message represented as data.

agent_message

Assistant text. The last completed one becomes finalResponse.

reasoning

Agent reasoning summary text.

command_execution

Command, aggregate output, exit code, and execution status.

file_change

Changed paths, add/delete/update kinds, and patch status.

mcp_tool_call

Server, tool, arguments, status, result, or error.

web_search

Web search activity and query.

todo_list

The agent's plan items and completion flags.

error item

A non-fatal warning or error item; it does not necessarily fail the turn.

Wire-format caveat: stdout events are cast after JSON.parse, not runtime-validated. The CLI can evolve ahead of the declared union. Include a defensive default branch and inspect unknown items rather than assuming the union is exhaustive at runtime.

Text and local images

Input is either one string or an array of text and local-image objects. The SDK does not support remote image URLs or raw binary image payloads.

multimodal.ts 
const result = await thread.run([
  { type: "text", text: "Compare these screenshots." },
  { type: "local_image", path: "./before.png" },
  { type: "text", text: "Focus on layout regressions." },
  { type: "local_image", path: "./after.png" },
]);

console.log(result.finalResponse);
  • Text entries are concatenated with exactly two newline characters.
  • Image positions relative to text are not preserved; every image becomes a CLI --image argument.
  • Paths are passed through unchanged. Resolve and validate them in your application when location matters.
  • An image-only or empty array produces an empty textual prompt.

Structured output

Pass a JSON Schema per turn. The SDK writes it to a temporary file for the CLI, but returns the generated JSON as an ordinary string.

structured.ts 
import { z } from "zod";
import { zodToJsonSchema } from "zod-to-json-schema";

const Audit = z.object({
  summary: z.string(),
  risks: z.array(z.object({
    file: z.string(),
    severity: z.enum(["low", "medium", "high"]),
  })),
});

const result = await thread.run("Audit authentication code.", {
  outputSchema: zodToJsonSchema(Audit, { target: "openAi" }),
});

const audit = Audit.parse(JSON.parse(result.finalResponse));
console.log(audit.risks);
Validate after parsing: outputSchema is typed as unknown. The SDK checks for a non-null, non-array object and serializes it, but does not parse or validate the model response. Zod integration is application-side.

Examples cookbook

Complete patterns for common Node.js integrations. Replace paths and models with values appropriate to your environment.

Read-only repository review

review.ts 
import { resolve } from "node:path";
import { Codex } from "@openai/codex-sdk";

const thread = new Codex().startThread({
  workingDirectory: resolve("../my-project"),
  sandboxMode: "read-only",
  modelReasoningEffort: "high",
});

const result = await thread.run(
  "Review architecture and identify the three highest-risk areas. " +
    "Cite relevant files and do not modify anything.",
);
console.log(result.finalResponse);

Implement, test, and inspect completed work

implement.ts 
import { Codex, type CommandExecutionItem } from "@openai/codex-sdk";

const thread = new Codex().startThread({
  workingDirectory: "/path/to/project",
  sandboxMode: "workspace-write",
  networkAccessEnabled: false,
});

const result = await thread.run(
  "Fix the validation bug, add focused tests, and run them.",
);

const commands = result.items.filter(
  (item): item is CommandExecutionItem => item.type === "command_execution",
);
for (const command of commands) {
  console.log(command.command, command.exit_code, command.status);
}
console.log(result.finalResponse);

Cancel on timeout

timeout.ts 
const controller = new AbortController();
const timeout = setTimeout(() => controller.abort(), 60_000);

try {
  const result = await thread.run("Perform a focused security review.", {
    signal: controller.signal,
  });
  console.log(result.finalResponse);
} finally {
  clearTimeout(timeout);
}

Run independent threads concurrently

parallel.ts 
const codex = new Codex();
const backend = codex.startThread({
  workingDirectory: "/path/to/project", sandboxMode: "read-only",
});
const frontend = codex.startThread({
  workingDirectory: "/path/to/project", sandboxMode: "read-only",
});

const [api, ui] = await Promise.all([
  backend.run("Audit API error handling."),
  frontend.run("Audit accessibility and loading states."),
]);
console.log(api.finalResponse, ui.finalResponse);

Each turn has its own child process. Parallel independent threads are straightforward; concurrent turns sharing one thread can race on persisted conversation state and should be avoided.

Production checklist

  • Run in Node.js, not a browser or edge runtime.
  • Use absolute, validated workspace and image paths.
  • Prefer read-only; grant writes and network access only when required.
  • Fully consume streams and handle both terminal events.
  • Use one in-flight turn per Thread.
  • Parse and validate structured output before using it.
  • Preserve thread.id only when local resumability is required.
  • Handle aborts, malformed JSONL, spawn failure, nonzero exit, and turn.failed.
  • Pin compatible SDK/CLI versions when overriding the binary.

Repository samples include basic_streaming.ts, structured_output.ts, and structured_output_zod.ts.

Sandbox, approval, and network controls

Thread options become CLI flags or config overrides on every turn. Omitted values defer to CLI, user, project, and policy configuration.

Option Values Effect
sandboxMode read-only, workspace-write, danger-full-access Filesystem capability boundary.
networkAccessEnabled boolean Overrides network access for workspace-write sandbox configuration.
webSearchMode disabled, cached, live Controls search behavior; wins over legacy webSearchEnabled.
approvalPolicy never, on-request, on-failure, untrusted CLI approval policy override. on-failure is a legacy alias for on-request behavior.
additionalDirectories string[] Adds accessible roots; write capability still depends on the effective sandbox.
Headless constraint: the exec transport cannot present interactive approval or user-input requests to your application. Requests that require interaction are rejected or canceled, so choose non-interactive policies and prompts appropriate for automation.

Global and thread configuration

Global CodexOptions configure CLI launch. ThreadOptions configure every invocation for one conversation.

configuration.ts 
const codex = new Codex({
  codexPathOverride: "/opt/codex/bin/codex", // optional
  baseUrl: process.env.OPENAI_BASE_URL,
  apiKey: process.env.OPENAI_API_KEY,
  config: {
    show_raw_agent_reasoning: false,
    sandbox_workspace_write: { network_access: false },
    mcp_servers: {
      internal: { command: "my-mcp-server" },
    },
  },
});

const thread = codex.startThread({
  model: "gpt-5.4",
  workingDirectory: "/path/to/project",
  modelReasoningEffort: "high",
  sandboxMode: "workspace-write",
  networkAccessEnabled: false,
  additionalDirectories: ["/path/to/shared"],
});
Global option Behavior
codexPathOverride Use a specific executable instead of packaged-binary discovery.
baseUrl Emits openai_base_url as a CLI config override.
apiKey Sets CODEX_API_KEY in each child process.
config Flattens nested objects to dotted keys and serializes values as TOML literals.
env When present, fully replaces inherited process.env before SDK-required additions.
Precedence: arbitrary global config is emitted first, then baseUrl, then thread-specific options. Later duplicate CLI overrides win.
Custom environment: env is not merged. Include every variable the child needs, potentially HOME, PATH, proxies, certificates, provider credentials, and CODEX_HOME.

Tools and MCP

The SDK does not register JavaScript callback functions as agent tools. Configure MCP servers through Codex configuration. Their calls appear as mcp_tool_call items with server, tool, arguments, status, result, and error fields.

Cancellation and failure modes

Pass an AbortSignal per turn. Node forwards it to the spawned child; aborting rejects buffered execution or streamed iteration.

abort.ts 
const controller = new AbortController();
process.once("SIGINT", () => controller.abort());

try {
  const { events } = await thread.runStreamed("Review the repository.", {
    signal: controller.signal,
  });
  for await (const event of events) {
    console.log(event);
  }
} catch (error) {
  if (controller.signal.aborted) console.error("Turn canceled");
  else throw error;
}
Failure Observed as
Agent turn failure in run() Generic Error with the turn message.
Agent turn failure in streaming turn.failed event; your loop decides whether to throw.
Top-level runtime error event { type: "error", message }; buffered run() does not directly throw for this event.
Nonzero exit or signal Rejected iteration with exit/signal and captured stderr.
Malformed JSONL Error("Failed to parse item: ...") with a cause.
Abort Node child-process abort error; no SDK-specific error hierarchy.

Resume local conversations

Turns are persisted by the CLI. Save the thread ID after execution starts, then construct a new thread wrapper later.

resume.ts 
const codex = new Codex();
const original = codex.startThread({ workingDirectory: "/path/to/project" });
await original.run("Analyze the migration plan.");

if (!original.id) throw new Error("Thread ID was not emitted");
await saveThreadId(original.id);

// In a later process:
const id = await loadThreadId();
const resumed = codex.resumeThread(id, {
  workingDirectory: "/path/to/project",
});
const next = await resumed.run("Add a rollback checklist.");
  • Ordinary storage is under $CODEX_HOME/sessions, typically ~/.codex/sessions.
  • resumeThread() does no immediate I/O or ID validation; lookup occurs on the next turn.
  • Sessions are local to the host and effective CODEX_HOME. Persisting an ID does not transfer its rollout.
  • The TypeScript SDK has no list, read, archive, fork, delete, compact, or export API.

Know the boundaries

Node-only runtime

Requires child processes, filesystem, readline, temp directories, and AbortSignal. It does not run in browsers.

No persistent server

Each turn pays process startup cost and gets a separate stderr/stdout lifecycle.

No JS callback tools

Use runtime tools and configured MCP servers instead of registering local SDK functions.

Small lifecycle surface

Only start and resume are exposed; session administration is not.

No typed error hierarchy

Failures are ordinary errors or stream events, depending on their source and execution mode.

Declarations can lag runtime

JSONL is not runtime-validated, so defensive event handling matters across CLI changes.

Release status: the source manifest uses 0.0.0-dev; release packaging writes the published version and injects its matching CLI dependency. Confirm and pin the package version available in your registry.
