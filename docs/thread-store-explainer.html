threadStore: the web thread cache

There is no class named threadStore. It is the IndexedDB object store named "thread" behind the EnvironmentCacheStore service.

Where it lives IndexedDB

  • apps/web/src/connection/storage.ts:45 — THREAD_STORE_NAME = "thread"
  • Created in the t3code:connection-runtime database (version 4) in openDatabase (storage.ts:130).
  • Holds the last-known OrchestrationV2ThreadDetailSnapshot per thread so a thread can show before the server responds.

Keys and values

  • Key: environmentId:threadId (threadCacheKey, storage.ts:368); the prefix lets clear(environmentId) delete one environment's threads by key range.
  • Value: JSON of StoredOrchestrationThreadSnapshot {environmentId, threadId, snapshot}. On load, IDs are checked; corrupt or old-schema records are discarded.

Operations

MethodWhat it does
loadThreadReads key; discards bad records and returns none
saveThreadEncodes and writes the snapshot
removeThreadDeletes the key
clearDeletes all threads for an environment (with shell, server config, VCS refs)

Callers client-runtime

packages/client-runtime/src/state/threads.ts

  • Subscribe: loadThread runs only if there is no in-memory resumeCache; failures log a warning and act as a miss.
  • Commit: saveThread after the snapshot commits, skipped if committed state no longer matches.
  • Delete: removeThread, only if this subscription still owns the resume cache.
