Streaming · architecture notes

Text streaming: opencode vs lightcode

opencode publishes every token as a small typed event onto one long-lived SSE connection and batches them on the client. lightcode forwards raw Codex notifications through one tRPC stream per request, and the renderer currently discards the text deltas.

How streaming works in opencode

Token to pixel, in two hops: server publishes events, client batches them.

The server never batches; every provider token becomes one event. All smoothing happens in the client queue.

  1. Provider to LLMEvent. packages/llm decodes the provider's SSE body into typed events: text-start, text-delta, text-end.
  2. Publish per delta. publish-llm-event.ts appends each delta to an in-memory buffer and publishes session.next.text.delta. On text-end it publishes Text.Ended with the joined text.
  3. Fan out over SSE. handlers/event.ts subscribes to the bus with a bounded queue (256), sends server.connected, then live events, plus a : heartbeat comment. Headers disable proxy buffering.
  4. Queue and coalesce. server-sdk.tsx reads with for await, pushes into a queue, and flushes on a 16 ms timer. coalesceServerEvents concatenates consecutive deltas for the same part.
  5. Reduce and render. The reducer appends the delta. text.ended replaces the text with the full value, so any drift is corrected.

Why the client coalesces

Without coalescing, every token is a reactive update. With it, render cost scales with frames, not tokens.

Live-only deltas, durable ends

The stream is a preview. The database row is the truth.

How streaming works in lightcode today

Same idea, fewer stages, and a dead end at the last one.

Everything up to queryAI works. The last hop reads chunk.params.delta and never writes it anywhere.

What works

Stdio notifications are filtered per thread and turn, buffered, and streamed to the renderer. The final answer is persisted at item/completed.

What is missing

No client accumulation, no batching, no reconnect, and turnId is never set, so stopTurn always throws.

What to borrow

  1. Accumulate in one store. Stream into ["messages", threadID] in the React Query cache with setQueryData, and treat the DB row as the truth.
  2. Coalesce on the client. Buffer deltas in a string and flush every ~16 ms (or requestAnimationFrame) so one flush is one render.
  3. Reconcile on end. When the turn completes, flush the buffer, then invalidate or overwrite with the stored final text, like text.ended.
  4. Make the turn cancellable. Capture turnId from turn/started, and interrupt on stop or client disconnect.
  5. Later: decouple stream from request. A shared event stream with heartbeat and reconnect would survive dropped connections. That is a larger change than the four above.
