Refactor plan

One context. Three clear owners.

Let TanStack Query own cached data. Keep chat coordination in one hook.

apps/novus/src/context/useAIChat.tsx

The split

01 · Projects

hooks/useProjects.ts

Own project loading and creation.

  • Query the project list.
  • Pick a folder and create via a mutation.
  • Invalidate projects after creation.
02 · Conversation

hooks/useChatSession.ts

Own the full chat lifecycle.

  • Query history by thread ID.
  • Send, stream, stop, and handle errors.
  • Track turns per thread and refresh titles.
03 · Shared context

context/useAIChat.tsx

Own selection and preferences.

  • Keep selected thread, model, and access.
  • Call useChatSession.
  • Expose state and actions to the UI.

Paths are relative to apps/novus/src/. The sidebar calls useProjects() directly.

Where TanStack Query fits

Data / actionApproach
ProjectsuseQuery(["projects"])
Threads in the sidebaruseQuery(["threads", projectId])
Message historyuseQuery(["messages", threadID])
Create project / send messageuseMutation; consume the stream inside send.
Optimistic messages / stream deltassetQueryData updates the message cache.
Title generatedUpdate selected title; invalidate the affected thread list.

Query keys shown in shorthand. Remove messagesByThread: the message cache becomes the single source of truth.

Keep the lifecycle safe

Load before sending. Ensure history is cached before adding optimistic messages. Cancel competing fetches and prevent refetches from overwriting an active stream.

Track each thread. Guard against duplicate sends before the first await. Stop the captured thread; clean up that request’s turn state in finally.

Keep history and streaming together. They update the same data. TanStack Query handles caching; the session hook still handles streaming and cancellation.

Proposed code, explained

Complete proposed hook and provider files below. The final section shows the changes needed in existing UI files.

What is useChatSession? An exported React hook, called once by the provider. It accepts the selected thread and preferences, then returns messages, loading/error state, and send/stop actions.

What does it hide? Loading history, adding optimistic messages, reading the stream, updating the cache, and tracking each thread’s request. UI components use useAIChat() to access this shared session; they do not create their own sessions.

01 · Extract project management

hooks/useProjects.ts owns the folder picker, query, and creation mutation. The sidebar receives data and actions from one place.

import { useMutation, useQueries, useQuery, useQueryClient } from "@tanstack/react-query";
import { trpcClient } from "../utils/trpc";

export function useProjects() {
  const client = useQueryClient();
  const projects = useQuery({
    queryKey: ["projects"],
    queryFn: () => trpcClient.getProjects.query(),
  });

  const createProject = useMutation({
    mutationFn: async () => {
      const { filePaths } = await window.electronAPI.openFolder();
      const path = filePaths[0];
      const projectName = path?.split(/[\\/]/).filter(Boolean).at(-1);
      if (!path || !projectName) return false;

      await trpcClient.addProject.mutate({ projectName, path });
      return true;
    },
    onSuccess: async (created) => {
      if (created) {
        await client.invalidateQueries({ queryKey: ["projects"] });
      }
    },
  });

  const threadQueries = useQueries({
    queries: (projects.data ?? []).map((project) => ({
      queryKey: ["threads", project.id],
      queryFn: () => trpcClient.getThreads.query({ projectID: project.id }),
    })),
  });

  const sidebarProjects = (projects.data ?? []).map((project, index) => ({
    ...project,
    threads: (threadQueries[index]?.data ?? []).map((row) => ({
      id: row.id,
      projectId: row.project_id,
      title: row.name,
      projectPath: project.path,
    })),
  }));

  return {
    projects: sidebarProjects,
    isLoading: projects.isPending || threadQueries.some((query) => query.isPending),
    error: projects.error ?? threadQueries.find((query) => query.error)?.error ?? null,
    createProject,
  };
}

02 · hooks/useChatSession.ts — complete file

Inputs: selected thread, model, access, and a title-update callback. Output: the exported ChatSession interface. Helpers and request bookkeeping stay private.

import { useRef, useState } from "react";
import { queryOptions, useMutation, useQuery, useQueryClient } from "@tanstack/react-query";
import { trpcClient, type MessageRow } from "../utils/trpc";
import type { thread } from "../components/sidebar/types";
import type { AIModelId, AIReasoningEffort } from "../lib/aiModelConfig";

export type AccessMode = "read-only" | "workspace-write" | "danger-full-access";
export type ChatMode = "build" | "plan";
export type AIModel = { model: AIModelId; thinking: AIReasoningEffort };

type Options = {
  currentThread: thread | null;
  model: AIModel;
  access: AccessMode;
  onTitleChanged: (threadID: string, title: string) => void;
};

export type ChatSession = {
  messages: MessageRow[];
  isLoadingMessages: boolean;
  isTurning: boolean;
  error: string | null;
  send: (text: string, mode: ChatMode) => Promise<void>;
  stop: () => Promise<void>;
};

type Request = {
  phase: "loading" | "connecting" | "streaming" | "finishing";
  stopRequested: boolean;
  stopInFlight: Promise<void> | null;
};

type SendInput = {
  thread: thread;
  text: string;
  mode: ChatMode;
  model: AIModel;
  access: AccessMode;
  request: Request;
};

type Status = { busy: boolean; error: string | null };
const errorText = (error: unknown) =>
  error instanceof Error ? error.message : "Something went wrong.";

const messageKey = (id: string) => ["messages", id] as const;

const messageOptions = (id: string) => queryOptions({
  queryKey: messageKey(id),
  queryFn: () => trpcClient.loadMessages.query({ threadID: id }),
  staleTime: Infinity,
  gcTime: Infinity,
  refetchOnWindowFocus: false,
  refetchOnReconnect: false,
});

export function useChatSession({
  currentThread, model, access, onTitleChanged,
}: Options): ChatSession {
  const client = useQueryClient();
  const active = useRef(new Map<string, Request>());
  const [statuses, setStatuses] = useState<Record<string, Status>>({});
  const threadID = currentThread?.id;
  const history = useQuery({
    ...messageOptions(threadID ?? ""),
    enabled: !!threadID,
  });

  function patchStatus(id: string, patch: Partial<Status>) {
    setStatuses((current) => ({
      ...current,
      [id]: { busy: false, error: null, ...current[id], ...patch },
    }));
  }

  // Stop errors remain visible; stream consumption continues until it ends.
  async function interrupt(id: string, request: Request) {
    if (request.stopInFlight) return request.stopInFlight;
    request.stopInFlight = (async () => {
      try {
        await trpcClient.stopTurn.query({ threadID: id });
      } catch (error) {
        request.stopRequested = false;
        if (active.current.get(id) === request) {
          patchStatus(id, { error: `Could not stop: ${errorText(error)}` });
        }
      } finally {
        request.stopInFlight = null;
      }
    })();
    await request.stopInFlight;
  }

  const sendMutation = useMutation({
    retry: false,
    mutationFn: async (input: SendInput) => {
      const { thread, text, mode, model, access, request } = input;
      const id = thread.id;
      const key = messageKey(id);
      await client.ensureQueryData(messageOptions(id));
      await client.cancelQueries({ queryKey: key, exact: true });
      if (request.stopRequested) return;

      const assistantID = crypto.randomUUID();
      client.setQueryData<MessageRow[]>(key, (messages = []) => [
        ...messages,
        { id: crypto.randomUUID(), role: "user", text },
        { id: assistantID, role: "assistant", text: "" },
      ]);

      request.phase = "connecting";
      const stream = await trpcClient.queryAI.query({
        threadID: id, message: text, model, mode, access,
      });

      let completed = false;
      for await (const event of stream) {
        if (event.method === "turn/completed") {
          completed = true;
          request.phase = "finishing";
          continue;
        }

        // Wait for response content before interrupting a newly started turn.
        if (event.method !== "item/agentMessage/delta") continue;
        const firstDelta = request.phase === "connecting";
        request.phase = "streaming";
        if (firstDelta && request.stopRequested) {
          await interrupt(id, request);
        }

        const delta = event.params.delta;
        client.setQueryData<MessageRow[]>(key, (messages = []) =>
          messages.map((message) =>
            message.id === assistantID
              ? { ...message, text: message.text + delta }
              : message,
          ),
        );
      }

      // Do not release the guard while an interrupt request is unresolved.
      await request.stopInFlight;
      request.phase = "finishing";
      if (!completed && !request.stopRequested) {
        throw new Error("The response stream ended before completion.");
      }
      if (!completed || request.stopRequested) return;

      try {
        const title = await trpcClient.getThreadTitle.mutate({ threadID: id });
        onTitleChanged(id, title);
        await client.invalidateQueries({ queryKey: ["threads", thread.projectId] });
      } catch (error) {
        patchStatus(id, { error: `Reply received; title refresh failed: ${errorText(error)}` });
      }
    },
  });

  async function send(value: string, mode: ChatMode) {
    const text = value.trim();
    if (!text || !currentThread || active.current.has(currentThread.id)) return;

    const id = currentThread.id;
    const request: Request = {
      phase: "loading", stopRequested: false, stopInFlight: null,
    };
    active.current.set(id, request); // Synchronous duplicate-send guard.
    patchStatus(id, { busy: true, error: null });

    try {
      await sendMutation.mutateAsync({
        thread: currentThread, text, mode, model, access, request,
      });
    } catch (error) {
      patchStatus(id, { error: errorText(error) });
    } finally {
      await request.stopInFlight;
      if (active.current.get(id) === request) {
        active.current.delete(id);
        patchStatus(id, { busy: false });
      }
    }
  }

  async function stop() {
    if (!threadID) return;
    const request = active.current.get(threadID);
    if (!request || request.phase === "finishing" || request.stopRequested) return;
    request.stopRequested = true;
    if (request.phase === "streaming") await interrupt(threadID, request);
    // Loading: skip send. Connecting: interrupt when the first delta arrives.
  }

  const status = threadID ? statuses[threadID] : undefined;
  return {
    messages: history.data ?? [],
    isLoadingMessages: !!threadID && history.isPending,
    isTurning: status?.busy ?? false,
    error: status?.error ?? (history.error ? errorText(history.error) : null),
    send,
    stop,
  };
}

Read it in order: useQuery displays history → send locks the thread → the mutation loads history and streams into its cache → finally unlocks it. return exposes only what the UI needs.

Why both refs and state? The ref blocks a second send immediately, before React rerenders. State makes busy/error changes visible to the UI. Messages live only in the query cache.

Cache policy: infinite stale/GC times preserve history even when a long-running thread is not selected. This keeps messages in memory for the window’s lifetime. Remove entries when deleting threads; explicitly refresh external changes only when idle.

Failure policy: keep partial text and show the error. Do not retry automatically: the server may already have accepted the message. Here isTurning includes setup and title refresh so a new send cannot overlap finishing work.

Current stop limitation: the client’s event type exposes only deltas and completion, so an early stop waits for the first delta. Immediate interruption during reasoning needs a typed turn-start event and a server-ready signal. Also, apps/server/lightThread.ts checks turnId in stopTurn() but never assigns it in the inspected code. That server issue must be fixed for interruption to succeed.

Lifetime: mount this hook once in the window-level provider. Switching threads keeps streams alive. A provider-unmount cancellation policy would need explicit transport/server support; this proposal does not imply that closing a window stops server work.

03 · context/useAIChat.tsx — complete file

Import the hook and its exported types. The provider translates the session’s short action names into the names existing UI components already use.

import { createContext, useContext, useState, type ReactNode } from "react";
import type { thread } from "../components/sidebar/types";
import {
  useChatSession,
  type AccessMode,
  type AIModel,
  type ChatSession,
} from "../hooks/useChatSession";

type AIContext = {
  currentThread: thread | null;
  setCurrentThread: (thread: thread) => void;
  modelSet: (model: AIModel["model"], thinking: AIModel["thinking"]) => void;
  access: AccessMode;
  accessSet: (access: AccessMode) => void;
  messages: ChatSession["messages"];
  messageSend: ChatSession["send"];
  stopTurn: ChatSession["stop"];
  isTurning: boolean;
  isLoadingMessages: boolean;
  error: string | null;
};

const aiContext = createContext<AIContext | undefined>(undefined);

export function AiChatProvider({ children }: { children: ReactNode }) {
  const [currentThread, setThread] = useState<thread | null>(null);
  const [model, setModel] = useState<AIModel>({
    model: "gpt-5.6-luna",
    thinking: "low",
  });
  const [access, setAccess] = useState<AccessMode>("workspace-write");

  const session = useChatSession({
    currentThread,
    model,
    access,
    onTitleChanged(threadID, title) {
      setThread((current) =>
        current?.id === threadID ? { ...current, title } : current,
      );
    },
  });

  return (
    <aiContext.Provider value={{
      currentThread,
      setCurrentThread: setThread,
      modelSet: (model, thinking) => setModel({ model, thinking }),
      access,
      accessSet: setAccess,
      messages: session.messages,
      messageSend: session.send,
      stopTurn: session.stop,
      isTurning: session.isTurning,
      isLoadingMessages: session.isLoadingMessages,
      error: session.error,
    }}>
      {children}
    </aiContext.Provider>
  );
}

export function useAIChat() {
  const context = useContext(aiContext);
  if (!context) {
    throw new Error("useAIChat must be used within an AiChatProvider!");
  }
  return context;
}

Exports: AiChatProvider creates the shared session; useAIChat reads it. useChatSession is exported from its own file, but only the provider calls it.

Result: the provider selects and shares. The session coordinates. TanStack Query stores fetched data.
